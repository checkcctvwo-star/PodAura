# 设备运行验证清单 (DEVICE_TESTING)

本文件是用户在真机上执行的运行时验证清单。**AI 仅保证 CI 编译通过 + 单元测试通过 + APK 产物生成；运行时转码成功必须由人工在真机验证。** CI（ubuntu）无 Android 设备/模拟器，无法跑仪器测试的运行时路径。

---

## 前置条件

- 一台 Android 真机（API 24+，即 Android 7.0+）。
- APK 已安装：从 CI artifact（`debug-apk`）或 GitHub Release 下载，选 `universal` 或与真机 ABI 匹配的包。
  - 安装命令：`adb install -r PodAura_<version>_<abi>_debug_GitHub.apk`
- （可选）电脑连手机跑 `adb logcat` 抓日志，便于故障定位：
  ```bash
  adb logcat | grep -iE "transcode|ffmpeg|skyd"
  ```

> 准备工作：确保手机存储空间充足；准备一个有音频 enclosure 的播客 RSS 源用于测试。

---

## 步骤 1：启动应用

- **操作**：打开 app。
- **预期**：正常进入主界面，无崩溃、无 ANR。
- **失败处理**：若闪退，抓 `adb logcat` 看崩溃栈，反馈。

---

## 步骤 2：配置 SAF 下载目录

- **操作**：设置 > 传输 > 下载目录，点选，用系统文件选择器选一个目录，授权。
- **预期**：返回设置页，"下载目录"项描述显示 URI（非"未设置"）。
- **说明**：`persistSafPermission` 会在授权有效期内持久化 SAF 树权限，并保存 `content://` URI 字符串到 `DownloadRootDirPreference`。
- **失败处理**：若显示仍为"未设置"，重试选目录；检查系统是否授予了该目录的访问权限。

---

## 步骤 3：订阅播客

- **操作**：添加一个播客 RSS 源（选有音频 enclosure 的源，例如某新闻播客），同步出剧集列表。
- **预期**：剧集列表正常加载，每集有音频信息。
- **失败处理**：若同步失败，检查网络 / RSS 源是否有效。

---

## 步骤 4：下载一集

- **操作**：点单集下载。等待下载完成（看下载列表或通知）。
- **预期**：下载到 `cacheDir` 临时目录（基座下载器）。下载完成事件触发后续转码 hook。
- **说明**：此时"自动转码为 MP3"应为开（默认开），下载目录已设（步骤 2）。

---

## 步骤 5：验证转码产出

- **操作**：等待转码完成（几秒~几十秒，视文件大小与码率）。用手机文件管理器打开步骤 2 所选的 SAF 目录。
- **预期**：
  - 目录下存在 `{节目名}/` 子目录；
  - 子目录内存在 `{集名}.mp3` 文件；
  - 文件大小合理（`finalSize` > 0，与码率对应：128 kbps 下 30 分钟约 28 MB，64 kbps 约一半）；
  - 用系统播放器打开可正常播放，音频内容与源一致。
- **命名模板验证**：文件名应符合当前模板（默认 TitleAndShow -> `{集名} - {节目名}.mp3`）。
- **失败处理**：
  - 文件不存在：检查下载记录 `transcodeStatus`，若为 `"failed"` 见下方异常处理。
  - 文件存在但不可播放：可能是源格式问题或转码中断，抓 logcat 看 FFmpeg 错误。

---

## 步骤 6：验证数据库记录（可选，需 adb）

- **操作**：通过 `adb` 查看下载记录（DownloadEntity）。
- **预期**：
  - `transcodeStatus = "success"`
  - `finalSize > 0`
  - `outputUri` 非空（`content://...` URI）
- **字段含义**：
  - `transcodeStatus`：`""` = 未转码/跳过，`"running"` = 转码中，`"success"` = 成功，`"failed"` = 失败
  - `finalSize`：最终输出 MP3 文件大小（字节）
  - `outputUri`：转码后文件在 SAF 的 `content://` URI
- **失败处理**：若 `transcodeStatus="failed"`，结合 logcat 定位。

---

## 步骤 7：重启验证 SAF 权限持久化

- **操作**：重启手机。重新打开 app，再下载一集。
- **预期**：仍能成功写 SAF（`persistSafPermission` 生效），产出 `{节目名}/{集名}.mp3`。
- **失败处理**：若写 SAF 失败（权限丢失），重新进入 设置 > 传输 > 下载目录，再选一次目录授权。某些厂商 ROM 可能在重启后撤销 SAF 授权，属系统行为。

---

## 步骤 8：命名模板切换

- **操作**：设置 > 传输 > 命名模板，分别切到三个模板，每次下载一集（最好同一播客的相邻集）。
- **预期**：文件名符合对应模板：

| 模板 | 预期文件名模式 | 示例 |
|---|---|---|
| TitleAndShow（标题 - 节目） | `{集名} - {节目名}.mp3` | `EP1_ Intro - Daily Tech.mp3` |
| ShowNumberTitle（节目 - E# - 标题） | `{节目名} - E{集号} - {集名}.mp3` | `Daily Tech - E1 - EP1_ Intro.mp3` |
| DateAndTitle（日期 - 标题） | `{发布日期} - {集名}.mp3` | `2026-07-31 - EP1_ Intro.mp3` |

- **说明**：非法字符（如 `:` `/` `?`）会被替换为 `_`。重名时追加 `(2)`、`(3)`。

---

## 步骤 9：码率切换

- **操作**：设置 > 传输 > 转码码率，分别选 `64 / 96 / 128 / 192` kbps，每次下载同一集（或时长相近的集）。
- **预期**：输出文件大小随码率变化（码率减半，文件约减半）。
- **说明**：码率仅影响输出 MP3 体积与质量，不影响文件名与目录结构。

---

## 步骤 10：保留原文件开关（可选）

- **操作**：开启"转码后保留原文件"，下载一集。
- **预期**：转码产出 MP3 到 SAF；同时 `cacheDir` 中保留原始下载文件（占用额外空间）。
- **关闭后**：转码后原始文件被删除，`cacheDir` 不残留。

---

## 异常处理与反馈

任一步骤失败：
1. 记录现象（哪一步、预期 vs 实际）。
2. 抓 logcat：
   ```bash
   adb logcat | grep -iE "transcode|ffmpeg|skyd"
   ```
3. 记录下载记录的 `transcodeStatus` / `finalSize` / `outputUri`（若可查）。
4. 反馈给维护者，附 logcat 截断与重现步骤。

---

## 诚实声明

- AI（本仓库的自动化开发）**仅保证**：CI 编译通过、单元测试通过、Debug APK 产物生成。
- **以上步骤 1-10 的运行时验证必须由用户在真机执行。** AI 无法在无设备环境下验证 FFmpegKit native 转码、SAF `content://` 写入、下载完成 hook 真实触发等运行时行为。
- 若运行时验证失败，不代表构建有问题，而是需要定位转码链路的具体故障点（源格式 / 权限 / 空间 / FFmpeg 错误）。
