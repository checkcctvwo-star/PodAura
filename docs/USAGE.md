# 使用说明 (USAGE)

本文件面向最终用户，说明播客下载 + 转 MP3 应用的安装、配置与日常使用。应用界面同时提供中文与英文（系统语言自动切换）。

> 平台限制：**仅 Android 支持下载 + 自动转 MP3。** iOS / macOS 桌面端不支持 SAF 转码流程。播放沿用基座 MPV 播放器；转码后写入 SAF（系统文件选择器目录）的 MP3 文件需用外部播放器或文件管理器打开。

---

## 1. 安装

1. 从 GitHub Release 页面下载 APK（选 `universal` 版本，或与手机 ABI 匹配的版本，如 `arm64-v8a`）。
2. 在手机上允许"未知来源"安装（系统设置 -> 应用安装权限）。
3. 点击 APK 安装。安装后应用图标名为 PodAura。

> APK 来自 CI 构建的 debug 签名包，可直接安装运行。详见 `docs/BUILD.md`。

---

## 2. 首次配置（设置 > 传输）

打开应用 -> 进入**设置** -> **传输**（Transmission）。该页面有 5 项配置：

### 2.1 下载目录（Download directory）

- 点选该项，弹出系统文件选择器（SAF），选一个目录并授权。
- 授权后会自动持久化权限（`persistSafPermission`），重启手机后仍可写入。
- 该目录是**转码后 MP3 的存放根目录**，按 `{节目名}/{集名}.mp3` 组织。
- 未设置时该项描述显示"未设置"。
- **必须设置**，否则自动转码不会执行（hook 会在根目录为空时直接跳过）。

### 2.2 自动转码为 MP3（Auto transcode to MP3）

- 开关，**默认开**。
- 开启：下载完成后自动转码为 MP3 并写入 SAF 目录。
- 关闭：使用基座原始下载行为（下载到 cacheDir，不转码、不写 SAF）。

### 2.3 转码码率（Transcode bitrate）

- 可选 `64 / 96 / 128 / 192` kbps，**默认 128**。
- 码率越高质量越好、文件越大；越低文件越小、质量越差。
- 描述栏显示当前值，如 `128 kbps`。点击弹出选择菜单。

### 2.4 命名模板（Naming template）

- 可选三项，**默认 TitleAndShow（标题 - 节目）**。点击弹出选择菜单，描述栏显示当前模板的中文名。

| 模板（设置值） | 显示名（中 / 英） | 文件名渲染模式 | 示例 |
|---|---|---|---|
| `TitleAndShow` | 标题 - 节目 / Title - Show | `{集名} - {节目名}` | `EP1_ Intro - Daily Tech.mp3` |
| `ShowNumberTitle` | 节目 - E# - 标题 / Show - E# - Title | `{节目名} - E{集号} - {集名}` | `Daily Tech - E1 - EP1_ Intro.mp3` |
| `DateAndTitle` | 日期 - 标题 / Date - Title | `{发布日期} - {集名}` | `2026-07-31 - EP1_ Intro.mp3` |

说明：
- 非法文件名字符（如 `:` `/` `?` 等）会被替换为 `_` 或移除（`sanitizeFileName`，扩展名固定 `.mp3`，文件名最长 200 字符）。
- 缺失字段按空字符串渲染。例如 `ShowNumberTitle` 在无集号时会渲染成 `节目名 - E - 集名.mp3`，因此优先选有集号的播客源以获得更整齐的命名。

### 2.5 转码后保留原文件（Keep original file after transcode）

- 开关，**默认关**。
- 关闭：转码并写入 SAF 后，删除 cacheDir 中的原始下载文件（节省空间）。
- 开启：保留 cacheDir 原文件。**注意：会占用额外存储空间**，仅在需要保留原始格式副本时开启。

## 3. 下载播客

1. **订阅播客**：在应用中添加播客 RSS 源（选一个有音频 enclosure 的源）。
2. 同步出剧集列表。
3. **点单集下载**。
4. 下载流程（开启自动转码且已设下载目录时）：
   1. 下载到 `cacheDir` 临时目录（基座下载器）。
   2. 下载完成触发 `TranscodeHook`：
      - 若源格式非 MP3（或未知）：用 FFmpegKit 转码（`-c:a libmp3lame`，按选定码率）到临时文件。
      - 若源已是 MP3（或格式未知但可复制）：直接复制。
   3. 写入 SAF：`{下载根目录}/{节目名}/{集名}.mp3`。
   4. 更新下载记录（`outputUri`、`transcodeStatus="success"`、`finalSize`）。
   5. 若未开"保留原文件"，删除 cacheDir 中的原始下载文件。

> 若"自动转码为 MP3"关闭，或下载目录未设置，则跳过转码步骤，使用基座原始下载行为。

---

## 4. 查看转码结果

1. 用手机文件管理器打开你选的 SAF 下载根目录。
2. 应见到 `{节目名}/{集名}.mp3` 结构。
3. **重名自动追加**：同一节目下若已有同名文件，新文件自动命名为 `集名 (2).mp3`、`集名 (3).mp3`，依此递增。
4. 用系统播放器或第三方播放器打开该 MP3，应可正常播放。

## 5. 故障排查

| 现象 | 排查 |
|---|---|
| **转码失败** | 在应用下载记录中查看 `transcodeStatus` 字段：`"success"`=成功，`"failed"`=失败，`""` = 未转码/跳过，`"running"`=转码中。失败可能原因：源音频格式不支持、存储空间不足、FFmpeg 内部错误。可抓 logcat：`adb logcat | grep -iE "transcode\|ffmpeg\|skyd"`。 |
| **SAF 权限丢失（重启后写 SAF 失败）** | 重新进入 设置 > 传输 > 下载目录，再选一次目录并授权。`persistSafPermission` 会再次持久化权限。某些系统厂商 ROM 可能在清理后台后撤销 SAF 授权，属系统行为。 |
| **找不到转码后的文件** | 确认 设置 > 传输 > 下载目录 已选且非"未设置"；用文件管理器确认所选目录下 `{节目名}` 子目录存在。若下载目录为空字符串，转码会被跳过。 |
| **下载了但没有 MP3 产出** | 确认"自动转码为 MP3"开关为开。若关闭，下载仅落到 cacheDir，不会写 SAF。 |
| **文件名出现 `_`** | 正常现象。模板渲染会清理非法文件名字符（如 `:` -> `_`），确保跨文件系统兼容。 |
| **空间不足** | 转码需要临时空间（源文件 + 临时输出）。开启"保留原文件"会进一步占用 cacheDir。低码率可减小输出体积。 |

---

## 6. 已知限制

- **仅 Android**：iOS / macOS 桌面端不支持 SAF 转码流程。
- **播放**：应用内播放沿用基座 MPV 播放器，针对 cacheDir / 应用可访问路径。转码后写入 SAF 的 MP3 文件需用外部播放器或文件管理器打开（SAF content:// URI 不在应用沙箱内）。
- **签名**：当前 APK 为 debug 签名（CI 构建）。正式 release 签名待后续配置。
- **运行时验证**：CI 仅保证编译通过。转码的运行时正确性需在真机验证（见 `docs/DEVICE_TESTING.md`）。
